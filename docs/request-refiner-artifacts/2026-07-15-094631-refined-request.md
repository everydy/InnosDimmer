## Refined Execution Request

Implement and verify two focused reliability improvements in the native macOS InnosDimmer menu-bar application.

First, extend display-target resolution so that a missing saved monitor does not immediately terminate a dimming operation. Inspect the current active display topology and automatically route the requested operation to an alternate display only when exactly one eligible external display is available. Exclude the CoreGraphics main display and every built-in display identified by `CGDisplayIsBuiltin`, including a built-in panel that is active but is not currently the main display. If no eligible external display exists, retain non-destructive failure behavior. If multiple eligible external displays exist, do not choose by array order; block the operation and emit an actionable diagnostic directing the operator to select a display. A temporary fallback must not overwrite the persisted preferred display, and reconnect reconciliation must restore priority to the saved display.

Second, install a standard macOS application menu with a `Quit InnosDimmer` item bound to `Command-Q`. The command must use the normal `NSApplication` termination path so `AppDelegate.applicationWillTerminate` continues to stop the menu-bar controller and clear software dimming, hotkeys, timers, observers, and popover state. Do not register `Command-Q` as a Carbon/global hotkey. The behavior is required while InnosDimmer is active; a process whose main event loop is completely frozen may still require macOS Force Quit and is outside the guarantee.

Use test-driven development: add a failing behavioral test for each new rule, confirm the expected failure, make the smallest production change, then rerun the narrow tests and the repository's Debug `build-for-testing` verification. Preserve the current AppKit architecture, display inventory/resolver ownership boundaries, settings schema, schedule behavior, shortcuts, and software-dimming backend.

- Constraints:
  - Never automatically dim a built-in display or the CoreGraphics main display as a fallback.
  - Never guess among multiple eligible external displays.
  - Do not visibly probe a sequence of candidate displays.
  - Do not overwrite the saved preferred display when using a temporary fallback.
  - Do not bypass `DisplayInventoryProviding`, `DisplayTargetResolver`, `BrightnessController`, or the existing software-dimming strategy.
  - Do not add dependencies, change the persisted settings schema, alter schedule policy, change shortcut bindings, add DDC/CI probing, or redesign UI surfaces.
  - Do not implement `Command-Q` as a global shortcut; use the standard AppKit main-menu action targeting normal application termination.
  - Treat complete process hangs as outside the `Command-Q` guarantee; document Force Quit as the recovery path for that case.
  - Protect unrelated user changes in the worktree and keep changes scoped to these two reliability behaviors.
- Success check:

  - Main-only and no-external configurations remain non-destructive.

  - Temporary fallback does not modify `DisplayTargetStore.selectedDisplay`.

  - The application has a standard Quit menu item whose key equivalent is `q` with the Command modifier and whose action follows `NSApplication.terminate`.
